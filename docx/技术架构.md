# 前端技术架构

## 1. 技术选型

| 类别 | 技术 | 版本 | 说明 |
|------|------|------|------|
| 框架 | Vue | 3.5.x | Composition API + `<script setup>` |
| 语言 | TypeScript | 6.x | strict 模式（vue-tsc 类型检查） |
| 构建工具 | Vite | 8.x | 开发服务器 + 生产构建 |
| 路由 | Vue Router | 5.x | History 模式，路由守卫鉴权 + Token 过期校验 |
| 状态管理 | Pinia | 3.x | Setup 函数式 Store |
| UI 组件库 | Element Plus | 2.x | 桌面端组件库 |

| 图标 | @element-plus/icons-vue | 2.x | Element Plus 官方图标 |

```

```

生产环境由后端或 Nginx 处理 CORS 和反向代理，前端为纯静态文件。

## 4. 核心模块设计

### 4.1 HTTP 请求层（src/utils/request.ts）

Axios 实例封装，职责：

- **请求拦截器**：从 localStorage 读 `accessToken`，附加 `Authorization: Bearer {token}`
- **响应拦截器**：解包后端 `{code, message, data}` 信封；`code !== 200` 时 `ElMessage.error` 提示
- **401 处理**：清除本地 `accessToken`/`refreshToken`，跳转登录页

```
请求发出 → 附加 JWT → 后端处理 → 响应 {code, message, data}
                                          │
                                    code === 200 → 返回 data
                                    code === 401（或 HTTP 401）→ 清除两个 Token → 跳转 /login
                                    其他 → ElMessage.error → reject
```

> 注：当前**未实现 Token 自动刷新重试**——401 直接清登录态跳转。`stores/auth.ts` 的 `refresh()` 已定义但未接入拦截器（见业务流程 §1.3）。

### 4.2 认证状态（src/stores/auth.ts）

Pinia Setup Store，职责：

- 管理 `accessToken`、`refreshToken`、`isLoggedIn`、`userInfo`
- Token 持久化到 localStorage，刷新页面不丢失
- `login()`：密码经 `hashPassword`（MD5）后传输，成功后落库 Token 并拉取用户信息
- `register()`：注册后自动登录（沿用原始明文密码再走一次 login）
- `fetchUserInfo()`：拉取当前用户资料（含 `roles`、`permissions`）
- `logout()`：清登录态并跳转 `/login`
- 派生能力：`isAdmin`、`hasRole(role)`、`hasPermission(code)`

### 4.3 路由守卫（src/router/index.ts）

`beforeEach` 全局守卫逻辑（依据 `meta.requiresAuth` 与 `meta.roles`）：

```
读取 accessToken，判定 tokenValid = 存在 && 未过期（isTokenExpired）
   │
   ├── 需鉴权页面（requiresAuth !== false）
   │     ├── tokenValid → 放行
   │     └── 无 Token / 已过期 → 清两个 Token → /login?redirect=原路径
   │
   ├── 已登录访问 /login、/register → /dashboard（避免重复登录）
   │
   └── meta.roles 限制页（如 ['admin']）
         └── 首次进入按需 fetchUserInfo，角色不匹配 → /dashboard
```

落地页规则：根路径 `/` 在 AdminLayout 下配置 `redirect: '/dashboard'`，登录后默认进入概览页。

### 4.4 布局系统（src/layouts/AdminLayout.vue）

```
/login、/register         → 独立布局（无导航）
其余页面                  → AdminLayout
┌──────────┬──────────────────────────────────┐
│          │ 顶栏（折叠按钮 + 用户下拉：个人中心 / 退出） │ ← el-header
│ 侧边栏    ├──────────────────────────────────┤
│ 概览      │                                  │
│ Agent管理 │         <router-view />          │ ← el-main
│ 创作工坊  │                                  │
│ 素材库    │                                  │
│ 系统管理 ▾│                                  │
│ 个人中心  │                                  │
└──────────┴──────────────────────────────────┘
                       │
                       ├─ ChatBubble（右下浮球，z-index 9999）
                       └─ ChatPanel（右侧滑入面板，z-index 9998）
```

- 菜单项按角色过滤（`roles` 为空则全员可见，含 `['admin']` 的仅管理员可见）
- 悬浮聊天（ChatBubble + ChatPanel）全局常驻于 AdminLayout，独立维护对话状态

### 4.5 流式请求（src/composables/useSSE.ts）

封装对话流式输出，返回 `{ streaming, send, abort }`：

- **底层**：基于 `fetch`（非 `EventSource`）发起 POST，手动从 `localStorage` 取 Token 加 `Authorization: Bearer`
- **端点**：`POST /api/chat/conversations/:conversationId/send`，请求体 `{ content }`
- **读取**：`response.body.getReader()` + `TextDecoder({ stream: true })` 循环读字节，**累计原始响应体文本**透传给 `onChunk`
- **中断**：`AbortController`，调用 `abort()` 取消；`AbortError` 静默处理

> 注：当前实现**未按 SSE 协议（`data:` 行）或 JSON 解析**，假定后端流式返回的是纯文本增量拼接。

### 4.6 JWT 工具（src/utils/jwt.ts）

`isTokenExpired(token)`：解析 JWT payload 的 `exp` 判定是否过期（`exp * 1000 < Date.now()`）。仅当能确认过期时返回 `true`；token 损坏或缺 `exp` 返回 `false`，交后端 401 兜底，避免前端误判踢人。base64url 解码时补齐 `=` padding，兼容浏览器 `atob`。

## 5. 类型系统

所有后端交互的数据类型定义在 `src/types/` 下：

| 文件 | 内容 |
|------|------|
| `api.ts` | `Result<T>` — 后端统一响应体 |
| `auth.ts` | `LoginRequest`、`RegisterRequest`、`TokenVO`、`RefreshTokenRequest` |
| `agent.ts` | `AgentVO`、`CreateAgentRequest`、`AgentCategory`（`'CHAT'\|'VIDEO'\|'IMAGE'`）、`AgentCategoryLabels` |
| `chat.ts` | `ConversationVO`、`MessageVO`、`CreateConversationRequest`、`SendMessageRequest` |
| `user.ts` | `UserVO`（含 `roles`、`permissions`）、`CreateUserRequest`、`UpdateUserRequest`、`ChangePasswordRequest`、`ChangePhoneRequest`、`UpdateProfileRequest`、`WxBindStatus` |
| `role.ts` | `RoleVO`、`CreateRoleRequest`、`UpdateRoleRequest` |
| `permission.ts` | `PermissionVO`、`PermissionTreeNode`、`CreatePermissionRequest`、`UpdatePermissionRequest` |

API 函数返回类型为 `AxiosResponse<Result<T>>`，调用方通过 `res.data.data` 获取业务数据。

## 6. API 模块

每个业务域一个文件，函数命名约定：

| 前缀 | 用途 | 示例 |
|------|------|------|
| `get` / `list` | 查询 | `getAgentList()`、`getProfile()` |
| `create` | 创建 | `createAgent(data)` |
| `update` | 更新 | `updateProfile(data)` |
| `delete` | 删除 | `deleteAgent(id)` |
| `assign` | 关联分配 | `assignUserRoles(id, roleIds)`、`assignRolePermissions(id, permIds)` |

新增后端接口时：先在 `src/types/` 加类型 → 再在 `src/api/` 加请求函数 → 页面调用。

## 7. 后端对接约定

| 约定项 | 说明 |
|--------|------|
| 响应格式 | 所有接口返回 `{code: number, message: string, data: T}` |
| 认证方式 | JWT Bearer Token，通过 `Authorization` 请求头传递 |
| Token 存储 | `accessToken` + `refreshToken` 存 localStorage（`request.ts` 在 401 时清除） |
| API 前缀 | 所有接口以 `/api` 开头（Vite 代理剥前缀转发到 8080） |
| 代理配置 | 开发环境 Vite 将 `/api` 代理到 `http://localhost:8080` |
| 业务路径 | 认证 `/auth/*`、Agent `/agents`、对话 `/chat/*`、用户 `/users`、角色 `/roles`、权限 `/permissions`、个人中心 `/user/profile/me/*` |

> 注：`/users`（复数，RBAC 管理）与 `/user/profile/me`（单数，个人中心）是两个不同的后端控制器。

## 8. 构建与部署

### 开发环境

```bash
npm run dev          # 启动 Vite 开发服务器（:5173），自动代理到后端
npm run type-check   # TypeScript 类型检查（vue-tsc）
```

### 生产构建

```bash
npm run build        # vue-tsc 类型检查 + vite build → dist/
npm run preview      # 本地预览 dist/ 产物
```

构建产物为纯静态文件（HTML + JS + CSS），部署到任意 Web 服务器或 CDN 即可。生产环境需配置 Nginx 反向代理将 `/api` 请求转发到后端服务。
