# 前端业务流程

> 本文同时描述「已实现」与「规划中」两类流程。未完成项以 🔧 / 【规划中】 标注。

## 1. 用户认证流程

### 1.1 注册流程

```
用户访问 /register
   │
   ▼
填写 用户名（5~50）+ 密码（6~256）+ 邮箱（选填，≤128）
   │
   ▼
前端表单校验（用户名/密码必填、长度、邮箱格式）
   │
   ▼
authStore.register() → POST /api/auth/register {username, password(MD5), email}
   │
   ├── 成功 → 注册后自动 login（复用明文密码再走登录）→ 存 Token + 拉取 userInfo
   │        → router.push('/') → 落地 /dashboard
   │
   └── 失败 → ElMessage 提示（如用户名已存在）
```

### 1.2 登录流程

```
用户访问 /login
   │
   ▼
填写 用户名 + 密码
   │
   ▼
authStore.login() → POST /api/auth/login {username, password(MD5)}
   │
   ├── 成功 → 存储 accessToken/refreshToken → fetchUserInfo()
   │        → 跳转 redirect 参数页面，无则 /dashboard
   │
   └── 失败 → ElMessage 提示（用户名或密码错误）
```

### 1.3 Token 刷新流程

> 🔧 **当前未实现自动刷新**。`stores/auth.ts` 的 `refresh()` 已定义但**未接入请求拦截器**。

实际现状：

```
任意请求 → 后端返回 401（Token 过期）
   │
   ▼
request.ts 响应拦截器捕获 401
   │
   ▼
清除 accessToken/refreshToken → 跳转 /login
（不尝试 refresh、不重试原请求）
```

【规划中】理想流程：

```
401 → 用 refreshToken 调 POST /api/auth/refresh
        ├── 成功 → 更新 Token → 重试原请求
        └── 失败（refreshToken 也过期）→ 清登录态 → /login
```

### 1.4 登出流程

```
用户点击用户下拉「退出登录」
   │
   ▼
authStore.logout()
   ├── 清除 localStorage（accessToken、refreshToken）
   ├── 重置状态（isLoggedIn = false、userInfo = null）
   └── 路由跳转 /login
```

### 1.5 路由守卫的 Token 过期校验

```
访问任意路由 → beforeEach 守卫
   │
   ▼
判定 tokenValid = accessToken 存在 && 未过期（isTokenExpired 依据 JWT exp）
   │
   ├── 需鉴权页 + !tokenValid → 清两个 Token → /login?redirect=原路径
   ├── 已登录访问 /login、/register → /dashboard
   └── meta.roles（如 admin）不匹配 → /dashboard
```

## 3. 创作工坊流程

> 🔧 **当前为前端原型（Mock）**：5 步向导 UI 已搭好，但全部使用本地 Mock 数据，`handleGenerate` 仅 `setTimeout` 模拟，**未接后端**。以下为「目标设计」流程，后端接入【规划中】。

### 整体流程（目标设计）

```
进入 /workshop/:id → Step 1: 故事梗概 → Step 2: 剧情扩展 → Step 3: 分镜生成
                  → Step 4: 角色设计 → Step 5: 视频生成 → 完成
```

> 与早期文档相比，当前向导为 5 步：**故事梗概 / 剧情扩展 / 分镜生成 / 角色设计 / 视频生成**（无独立的「图片生成」步骤，故事梗概输入独立为第一步）。

### 各步交互（目标设计）

- **Step 1 故事梗概**：用户输入/编辑原始故事创意
- **Step 2 剧情扩展**：AI 基于 Step 1 流式生成完整剧情（SSE 打字机效果），可重新生成
- **Step 3 分镜生成**：AI 拆分镜头，生成 镜头描述/运动/时长/对白
- **Step 4 角色设计**：AI 提取并设计角色外貌
- **Step 5 视频生成**：基于前序成果生成视频片段

每步支持查看、编辑、重新生成、确认后进入下一步。

### 流式交互（目标设计）

```
POST /api/chat/conversations/:id/send {content: 故事梗概}
   │
   ▼
后端流式返回（当前前端按"累计原始文本"读取，见技术架构 §4.5）
   │
   ├── 收到增量文本 → 追加到展示区
   └── 流结束 → 保存完整内容
```

### 当前实现现状（Mock）

```
currentStep(0~4) 控制步骤切换；nextStep/prevStep 前进后退
   │
   ▼
storyInput / mockPlot / mockStoryboards / mockCharacters / mockVideos 均为本地静态数据
   │
   ▼
handleGenerate() → setTimeout 1.5s → ElMessage「生成完成（Mock 数据）」
```

## 5. Agent 管理流程（/agents，仅 admin）

Agent 是可配置的外部模型接入，按**固定分类**组织：

| 分类（枚举） | 标签 | 用途 |
|---|---|---|
| `CHAT` | 对话 | 悬浮聊天面板选用 |
| `VIDEO` | 视频 | 视频生成 |
| `IMAGE` | 生图 | 图片生成 |

> 分类为前端写死的枚举（`AgentCategory`），**无分类的增删改**。

```
访问 /agents（需 admin 角色）
   │
   ▼
getAgentList() → 按 category 分组（groupedAgents，可折叠）
   │
   ▼
顶部：名称搜索 + 分类筛选下拉
   │
   ▼
每个分类区块：
   ├── 「+ 新增」→ 弹窗填写（name/description/apiUrl/apiKey/model/status/category/configJson）
   ├── 卡片：编辑、删除
   └── createAgent / updateAgent / deleteAgent
```

## 6. RBAC 权限管理流程（/system/*，仅 admin）

权限模型：用户 ← 角色 ← 权限（用户通过角色间接获得权限）。

### 6.1 用户管理（/system/users）

```
getUserList()（前端分页/搜索：用户名、状态）
   │
   ▼
操作：
   ├── 新增（username/nickname/email/phone/status）
   ├── 编辑（nickname/email/phone/status；username 不可改）
   ├── 删除
   ├── 行内状态启停开关 → updateUser(id, {status})
   └── 分配角色（弹窗多选）→ getUserRoleIds 回填 → assignUserRoles(id, roleIds)
```

### 6.2 角色管理（/system/roles）

```
getRoleList()（前端分页/搜索）
   │
   ▼
操作：
   ├── 新增（name/code/sort/status/remark）
   ├── 编辑（code 不可改）
   ├── 删除
   └── 分配权限（el-tree 多选）→ getRolePermissions 回填
        → 收集选中 + 半选节点 → assignRolePermissions(id, permissionIds)
```

### 6.3 权限管理（/system/permissions）

```
getPermissionList() → buildPermissionTree() 组装为树表
   │
   ▼
操作：
   ├── 新增（顶级或子权限，parentId 由 tree-select 选择）
   │     字段：name/code/type(1=菜单,2=按钮)/path/icon/sort/status
   ├── 编辑
   └── 删除
```

## 7. 个人中心流程（/profile）

左右布局：左侧头像，右侧 Tabs（基本信息 / 修改密码 / 账号绑定）。

```
getProfile() → 回填资料
   │
   ├── 基本信息：查看 username(只读)、phone(只读)、注册时间、角色标签
   │             可改 nickname、email → updateProfile → 同步 authStore.userInfo
   │
   ├── 头像上传：el-upload 自定义上传 → uploadAvatar(file) [PUT /user/profile/me/avatar]
   │             → 返回新 URL → 更新本地 + authStore.userInfo.avatar
   │
   ├── 修改密码：旧密码 + 新密码 + 确认（提交前 hashPassword）
   │             → changePassword → 成功后 authStore.logout() 强制重登
   │
   ├── 改手机号：弹窗 新手机号 + 6 位验证码 → changePhone【验证码发送为规划中】
   │
   └── 账号绑定（微信）：getWxBindStatus 查看（openid 脱敏）/ unbindWx 解绑
                          （仅能解绑已存在的绑定，无"去绑定"入口）
```

## 8. 悬浮聊天流程

全局常驻于 AdminLayout 的对话入口（非独立页面）。

```
ChatBubble（右下浮球）→ 点击 → 打开 ChatPanel（右侧滑入，自带遮罩）
   │
   ▼
ChatPanel 独立维护对话状态（不依赖 Pinia）：
   ├── getAgentList('CHAT') → 仅取对话类 Agent
   ├── getConversations / getMessages / createConversation
   │
   ▼
选 Agent 即创建对话 → 输入消息
   │
   ▼
useSSE().send('/api/chat/conversations/:id/send', {content}, onChunk)
   ├── onChunk：直接更新本地 messages 最后一条 assistant 消息（累计文本）
   └── 流结束 → 完整内容入列
```

> ⚠️ `views/chat/List.vue`、`Detail.vue` 是早期独立页面方案，**当前未挂路由、未被引用**；实际生效的对话 UI 是上述浮窗方案。
